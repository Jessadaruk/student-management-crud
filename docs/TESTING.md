## ตรวจ CRUD ผ่านหน้าเว็บจริง

1. อ่านข้อมูลตัวอย่าง 5 คน แสดง ID รหัส ชื่อ อีเมล สาขา ชั้นปี สถานะ และปุ่มจัดการครบ
2. เพิ่ม TEST-CRUD-001 ชื่อ “นักศึกษา ทดสอบ” อีเมลว่าง บันทึกสำเร็จและปรากฏในตาราง
3. แก้ชื่อเป็น “นักศึกษา แก้ไขแล้ว” อีเมล test@example.com ชั้นปี 4 และสถานะไม่ใช้งาน บันทึกและแสดงค่าที่แก้ครบ
4. ตรวจการลบด้วยหน้าต่างยืนยันของเวอร์ชันสุดท้ายโดยเพิ่ม TEST-DELETE-002 กดลบแล้วกด “ยกเลิกการลบ” รายการยังอยู่ จากนั้นกด “ยืนยันการลบ” รายการหายจากตาราง
5. ข้อมูลทดสอบถูกลบแล้ว เหลือข้อมูล seed 5 รายการ
6. ค้นหา “เจษฎารักษ์” ได้ 1 รายการ กดล้างคืนรายชื่อทั้งหมด
7. ฟอร์มว่างถูก browser ปฏิเสธ ตรวจ validity.valueMissing เป็น true
8. รหัสซ้ำ 673450207-3 ถูก server ปฏิเสธด้วยข้อความภาษาไทย หลังแก้ไขฟอร์มยังคงค่าชื่อที่กรอกไว้
9. Unit tests ตรวจ required ที่มีแต่ช่องว่าง อีเมลผิด ชั้นปี 0/9/ทศนิยม/ข้อความ และสถานะไม่ถูกต้อง
10. ทดสอบ viewport 390 × 844 ไม่มีการล้นแนวนอนของหน้า ตารางเลื่อนภายใน container ได้
11. ไม่พบ console error ในหน้ารายชื่อหลังตรวจครั้งสุดท้าย

## ปัญหาที่แก้ไข

- Prisma 6 บนเครื่องนี้ต้องมีไฟล์ SQLite ก่อน migration: เพิ่ม scripts/prepare-db.mjs ที่สร้างเฉพาะไฟล์ที่ยังไม่มี
- Next.js ไม่อนุญาต re-export dynamic config: ประกาศค่าที่ /students โดยตรง
- ฟอร์มล้างค่าหลังแจ้งรหัสซ้ำ: ส่งค่ากลับใน ActionState และเติมค่าฟอร์มอีกครั้ง
- Prisma engine ถูกล็อกหาก generate ระหว่างเซิร์ฟเวอร์ทำงาน: หยุดเซิร์ฟเวอร์และทดสอบ setup บนฐานข้อมูลใหม่จนผ่าน บันทึกวิธีแก้ใน README

## GitHub

เครื่องนี้ไม่มี GitHub CLI และ browser แสดงหน้าลงชื่อเข้าใช้ GitHub ตัว connector เชื่อมต่อบัญชีได้แต่ไม่มีคำสั่งสร้าง repository จึงยังไม่ได้สร้างหรือ push repository และยังตรวจ README บน GitHub ไม่ได้ คำสั่ง authentication และสร้าง Public Repository อยู่ใน README
